# Roadmap format — `pwdev-roadmap/1`

The roadmap of a PRD lives in `.planning/prds/<slug>/roadmap/`. Markdown files are for
people; `roadmap.json` is the machine contract that `scripts/roadmap-check.py` validates
and that `/pwdev-github:publish` consumes. Both must describe the same roadmap.

## Tree

```text
.planning/prds/<slug>/roadmap/
├── roadmap.json        machine contract (below)
├── ROADMAP.md          index with relative links + approval line
├── TRACEABILITY.md     requirement ↔ feature, both directions
├── RISKS.md            PRD risks mapped to the features that carry them
├── DEPENDENCIES.md     GENERATED by roadmap-check.py — never written by hand
├── STORIES.md          GENERATED — stories per feature, status, CA and RN
├── stories/            GENERATED — one US-NN-<slug>.md per story
└── F01-<slug>/
    ├── PHASE.md
    └── F01-E01-<slug>/
        ├── EPIC.md
        └── F01-E01-FT01-<slug>.md     one file per feature; its tasks live inside it
```

## Hierarchy and IDs

```text
Phase   F01                  a releasable milestone with independent user value
Epic    F01-E01              a coherent functional group
Feature F01-E01-FT01         a verifiable deliverable, with acceptance criteria
Task    F01-E01-FT01-T01     atomic: one day at most, five files at most
```

A child ID always extends its parent ID. Slugs are lowercase, hyphenated, unaccented.
Limits: at most 8 tasks per feature, 8 features per epic, 50 features overall.

## `roadmap.json`

```json
{
  "schema": "pwdev-roadmap/1",
  "meta": {
    "slug": "catalogo-produtos",
    "product": "Loja",
    "title": "Catálogo de produtos",
    "prd": ".planning/prds/catalogo-produtos/PRD.md",
    "prd_version": "1.0.0",
    "language": "pt-BR"
  },
  "requirements": ["FR-01", "FR-02", "NFR-01"],
  "nodes": [
    {"id": "F01", "type": "phase", "title": "Fundação", "parent": null, "path": "F01-fundacao/PHASE.md"},
    {"id": "F01-E01", "type": "epic", "title": "Acesso", "parent": "F01", "path": "F01-fundacao/F01-E01-acesso/EPIC.md"},
    {"id": "F01-E01-FT01", "type": "feature", "title": "Login de administrador", "parent": "F01-E01",
     "path": "F01-fundacao/F01-E01-acesso/F01-E01-FT01-login.md",
     "priority": "must", "estimate": "M", "intensity": "Standard",
     "requirements": ["FR-01", "NFR-01"],
     "acceptance": ["Credencial inválida retorna erro sem revelar qual campo falhou"]},
    {"id": "F01-E01-FT01-T01", "type": "task", "title": "Modelo de usuário com hash de senha",
     "parent": "F01-E01-FT01", "path": "F01-fundacao/F01-E01-acesso/F01-E01-FT01-login.md"}
  ],
  "edges": [
    {"from": "F01-E01-FT01", "to": "F01-E02-FT01", "kind": "technical"}
  ],
  "rules": [
    {"id": "RN-01", "title": "Bloqueio após tentativas inválidas",
     "rule": "Após 5 tentativas inválidas em 15 minutos, a conta fica bloqueada por 30 minutos.",
     "example": "5 senhas erradas às 10:00–10:10 → login volta às 10:40."}
  ],
  "stories": [
    {"id": "US-01", "feature": "F01-E01-FT01", "title": "Entrar como administrador",
     "persona": "administrador da loja", "action": "entrar com e-mail e senha",
     "value": "gerenciar o catálogo sem expor a área administrativa",
     "priority": "must", "status": "draft", "rules": ["RN-01"], "depends_on": [],
     "out_of_scope": "Login social.",
     "acceptance": [
       {"id": "CA-01", "path": "happy", "type": "gherkin",
        "text": "Dado que sou administrador ativo\nQuando informo e-mail e senha corretos\nEntão entro no painel"},
       {"id": "CA-02", "path": "error", "type": "gherkin", "rules": ["RN-01"],
        "text": "Dado que errei a senha 5 vezes em 15 minutos\nQuando tento entrar\nEntão vejo a conta bloqueada por 30 minutos"}
     ]}
  ]
}
```

| Field | Rule |
|---|---|
| `requirements` | every requirement ID of the PRD (`FR-xx`, `NFR-xx`) |
| `nodes[].path` | relative to the roadmap directory; tasks point to their feature file |
| feature `priority` | `must \| should \| could \| wont` (MoSCoW, inherited from its FRs) |
| feature `estimate` | `S \| M \| L` (weights 1, 2, 3 on the critical path) |
| feature `intensity` | `Quick \| Standard \| Full` — how much process the feature deserves |
| feature `requirements` | at least one; each must exist in top-level `requirements` |
| feature `acceptance` | at least one verifiable criterion |
| `edges[]` | `{from: A, to: B}` means **B depends on A** (A blocks B) |
| edge endpoints | features or tasks only; never a task and its own feature |
| edge `kind` | `technical \| data \| external \| decision` |
| `rules[]` | copy of the PRD `### Business Rules` (`RN-xx`, `title`, `rule`, `example`, optional `exceptions`) — the PRD stays the source |
| `stories[]` | user stories per feature — format, INVEST, CA and RN rules in [user-stories.md](user-stories.md) |
| story `status` | `draft` (written by the roadmap writer) or `ready` (only after `prd-stories` with the human) |
| story `acceptance[]` | `CA-xx` local to the story; `path` `happy \| error \| edge`; `type` `gherkin \| check`; optional `rules` |
| story `depends_on` | other `US-xx` of the same roadmap |

## What the checker enforces

`roadmap-check.py <roadmap.json>` prints `PASS` or `FAIL` plus one line per error:
schema, ID patterns, duplicates, parent type and prefix, missing files, features
without acceptance or origin, every `FR-xx` covered by a feature, split limits,
dangling or duplicate edges, and dependency cycles (the cycle is printed).
On `PASS` it computes the **waves** (topological levels of features; task edges lift
to their features) and the **critical path**, and writes `DEPENDENCIES.md`.

When `stories` is present it also enforces [user-stories.md](user-stories.md): story and CA
IDs, feature exists, persona named (never "the system"), action/value present and not
circular, MoSCoW, 1–5 stories per feature, every feature with at least one story, at most 8 CA,
Gherkin with Given/When/Then (Dado/Quando/Então), RN that exist in `rules[]`, and — for `ready`
stories — 3–8 CA with a happy and an error/edge path and every listed RN verified by a CA. It
warns on vague terms ("rápido", "intuitivo"…), generic personas and RN applied by no story, then
writes `STORIES.md` and `stories/US-NN-<slug>.md` (marked as generated; stale generated files
are removed). A roadmap without `stories` still passes, with a warning.
