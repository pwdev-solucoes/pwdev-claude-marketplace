# Autonomous loop contract

The loop is provider-neutral and bounded to one, two, or three iterations (three by default). It consumes a ready `TASK-NNN` identifier and publishes one atomic JSON record below `.planning/sdd-composy/loops/`. Legal active transitions are `running -> running`, or `running ->` a terminal reason. A terminal record is immutable through this interface. The complete set of terminal reasons is the `TERMINAL` tuple in `scripts/sdd_loop.py`; in human terms: completion, iteration cap, missing progress (identical diff or identical failure), scope expansion or drift, architectural ambiguity or new architecture, destructive action or request, external authorization, repeated environment failure, a third rejection, and cancellation. Completion requires fresh verification evidence; a phrase alone is never proof. Runtime adapters own provider-specific command vectors.

Use `python3 scripts/sdd_loop.py [--root REPO] start TASK-001 --task-state <tasks/<prd-slug>.json> --human-approved [--max-iterations N]`, `status LOOP-ID`, `continue LOOP-ID --task-state <...> --human-approved [--outcome progress|complete|...]`, or `cancel LOOP-ID`. `start` and `continue` refuse to run without `--human-approved`.
