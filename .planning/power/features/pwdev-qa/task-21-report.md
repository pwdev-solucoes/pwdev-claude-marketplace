## Implemented contract

- `qa-report` requires separately explicit manifest and project-root paths and makes exactly one
  allowed process invocation: `qa_report.py report --manifest PATH --project-root PATH`.
- Report validates the complete acceptance-criterion record, contract review, schema, evidence,
  sanitization, defects, limitations, and verdict through the existing exporter. HTML and PDF
  derive from the same normalized manifest.
- Stored test and evidence commands remain inert. Report neither executes nor re-runs tests,
  retries a failed export, mutates results, nor derives the QA verdict from the exit code.
- Export diagnostics, sanitization outcomes, QA verdict, export status, output directory, and
  publication attestation remain visible. A partial diagnostic directory is never called a
  complete report.
- `qa-status` summarizes the recorded criteria, cases/attempts, results, evidence/sanitization,
  current and out-of-scope defects, limitations, authorization, metrics, verdict, and next valid
  action without writing or changing any product or QA state.
- Both workflows consult only installed applicable specialists. Missing applicable expertise is
  a limitation, and specialist guidance never expands authorization or rewrites source records.
- Both Claude wrappers only load the shared portable body, forward `$ARGUMENTS` with repository
  context, preserve objective/constraints/limitations/authorization, and return the shared result
  unchanged. The shared bodies contain no Claude-only tokens.
