## Implemented contract

- `qa-report` requires separately explicit manifest and project-root paths and makes exactly one
  allowed process invocation: `qa_report.py report --manifest PATH --project-root PATH`.
- Report validates the complete acceptance-criterion record, contract review, schema, evidence,
  sanitization, defects, limitations, and verdict through the existing exporter. HTML and PDF
  derive from the same normalized manifest.
- Stored test and evidence commands remain inert. Report neither executes nor re-runs tests,
  retries a failed export, mutates results, nor derives the QA verdict from the exit code.
- Export diagnostics, sanitization outcomes, QA verdict, export status, output directory, and
  publication attestation remain visible. A partial diagnostic directory is never called a
  complete report.
- `qa-status` summarizes the recorded criteria, cases/attempts, results, evidence/sanitization,
  current and out-of-scope defects, limitations, authorization, metrics, verdict, and next valid
  action without writing or changing any product or QA state.
- Both workflows consult only installed applicable specialists. Missing applicable expertise is
  a limitation, and specialist guidance never expands authorization or rewrites source records.
- Both Claude wrappers only load the shared portable body, forward `$ARGUMENTS` with repository
  context, preserve objective/constraints/limitations/authorization, and return the shared result
  unchanged. The shared bodies contain no Claude-only tokens.

## Correction round 1

Review source: `.planning/power/features/pwdev-qa/task-21-review.md`.

### Root cause

The original oracles proved that relevant words and one literal CLI string were present, but did
not prove an intact positive obligation or reject a later contradictory permission. Consequently,
the command-string count could not detect a second exporter invocation described without the
literal command; broad regexes crossed adversative clauses; and evidence/status fields found
elsewhere could mask explicit instructions to skip validation or discard recorded state.

The correction requires complete normalized clauses for one exporter invocation, inert command
handling, pre-render evidence validation, same-manifest rendering, status-only behavior,
field-preserving summaries, and absence of report/evidence effects. Separate sentence-level
oracles reject any additional execution/export/generation/invocation clause, and destructive
status sentences are checked independently for every protected field.

## Correction round 2

Review source: `.planning/power/features/pwdev-qa/task-21-review.md` (quality review round 2).

### Root cause

The round-1 negative scans recognized only base-form destructive verbs. They rejected modal
phrases such as `may skip` and imperatives such as `Discard`, but missed third-person active forms
(`skips`, `discards`) and passive forms (`may be skipped`). Because the valid positive clauses
remained present, their exact assertions could not expose an additional contradictory sentence.

The correction introduces a shared structural clause scanner. It splits sentences and
adversative clauses, recognizes active/passive inflections of skip/ignore/bypass/omit and
discard/drop/omit/ignore/remove, binds each destructive verb to its protected object, and accepts
explicitly negated clauses. Protected status fields use word-bounded singular/plural patterns, so
valid prose such as `justified` cannot accidentally match `ID`.

### Reproduction and mutation RED

Before changing the oracle, both evidence-validation contradictions survived together:

```text
It skips evidence validation. Evidence validation may be skipped.
Ran 1 test in 0.002s
OK
```

Likewise, a probe containing the ten independent `It discards <field>` sentences survived the
old status test:

```text
Ran 1 test in 0.001s
OK
```

After strengthening the oracle, the same report probe failed once and identified both invalid
clauses. The same status probe failed ten subtests independently for `ID`, `status`, `expected`,
`observed`, `evidence reference`, `sanitization`, `current`, `superseded`, `scope decision`, and
`missing item`. Both mutations were reverted after their RED runs.

Valid negative controls remained accepted: `It never skips evidence validation`, `Evidence
validation must not be skipped`, `It does not discard ID`, and the existing `instead of dropping
them` language. The unmodified contracts also remained green.
