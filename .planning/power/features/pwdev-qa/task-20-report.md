## Implemented contract

- `qa-review` preserves objective, target, requirements, results, limitations, findings,
  approvals, and authorization; it reviews requirements and coverage and emits traceable findings
  without correcting or mutating product, tests, contracts, evidence, approvals, or QA state.
- Review selects installed applicable specialists, beginning with
  `qa-specialist-requirements`; unavailable applicable expertise is an explicit limitation and
  specialist guidance never expands authorization.
- `qa-release` lists failures and pending items separately, consumes
  `qa-specialist-readiness`, preserves risk/limitation records, and keeps the human release/risk
  decision distinct from the QA verdict and recommendation.
- Release verdict precedence is explicit: a proven current in-scope failure is `FAIL`; otherwise
  pending information/work/evidence/risk/decision or zero applicable criteria is `BLOCKED`;
  `PASS` requires a complete catalog, every applicable criterion `PASS`, no current in-scope
  defects, and no failure or pending item.
- Both workflows preserve the production/external-effect authorization boundary, treat report
  export and stored commands as inert, and never publish, push, merge, deploy, install, or correct
  product code automatically.
- Both Claude wrappers only load the shared portable body, forward `$ARGUMENTS` with repository
  context, preserve objective/constraints/limitations/authorization, and return the shared result
  unchanged.

## Correction round 1

Review source: `.planning/power/features/pwdev-qa/task-20-review.md`.

### Root cause

The original oracles matched broad nearby language instead of the complete invariants. The review
test prohibited product mutation but did not independently protect tests, contracts, approvals,
evidence, findings, and state or reject contradictory permission. The release test accepted a
generic separation of the human decision from the QA verdict without requiring all five audit
fields, and its alternation allowed `no failure` alone to satisfy the `PASS` guard.

### Mutation RED evidence

The test oracle was strengthened before changing the release contract. Against the unchanged
contract, the focused pair returned six failures because pending work, risk, limitation, evidence,
gate, and required decision were not each named independently as forbidden under `PASS`.

Each reviewed invalid mutation was then applied and reproduced in isolation:

- changing the read-only review sentence to permit modification caused
  `test_review_is_read_only_and_reports_requirements_coverage_and_findings` to fail;
- removing `timestamp` from the human decision record caused
  `test_release_keeps_qa_verdict_and_human_decision_separate` to fail its dedicated field check;
- reducing the `PASS` rule to absence of a proven failure caused six dedicated pending-condition
  subtests to fail.

All probe mutations were reverted. The release contract now spells out absence of pending work,
risk, limitation, evidence, gate, and required decision separately.
